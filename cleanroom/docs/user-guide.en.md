# Using T2AG

T2AG connects source material, direct explanations, examples, practice, actual feedback and learning plans. A teacher may explain or ask a question as the material requires. A correct answer is evidence for that answer, not automatic proof of lasting mastery.

## Getting to know you

Start with what you want to learn and how you like to learn. Add any materials, background, time constraints and preferences you have; there is no mandatory questionnaire to complete first. Missing facts stay unknown. Choose Chinese or English, then review an editable plan before starting.

```text
Your goal, materials and preferences
↓
Editable courses, teachers and schedule
↓
Your acceptance of the actual plan
↓
Create the courses and start the first activity
```

Mastery supports textbook, goal and project learning modes. Project courses use reproducible external milestones. Praxis courses use real actions, feedback and explicit uncertainty.

Low-governance reading can span several books under one intent. Upgrade it to a course only through an explicit decision. Reading records and flexible bindings do not automatically consume group capacity.

## Resume learning

Name the course you want to continue. Your teacher recovers the activity, stopping point, pending wording, open questions and next step. Maintenance and review work do not start a lesson automatically. If history conflicts, resolve the part that affects continued learning.

A textbook session must consume appropriate evidence for every page in its current Scope. Preparation, historical scans and hashes cannot replace current-session reading. Layout-sensitive or unknown pages require full-page images; other pages may use verified full text. Scanning is distinct from teaching and coverage.

## Continue between phone and computer

A phone controlling a task on the same computer uses the same course, sources and progress. There is no separate mirror upload or manual sync. After a disconnect, check whether the original action was saved before continuing from its actual stopping point.

Compatibility exchange is needed only for an explicitly chosen independent classroom that cannot access the instance. A connection failure does not automatically start another classroom, and changing devices does not grant permission to advance.

## Classroom flow

```text
Original material, location, order and role
↓
Verified pages read in the current session
↓
Teacher arrangements mapped to the source
↓
Explanation, examples, demonstrations or questions
```

After an answer, feedback and saving have separate outcomes:

```text
Actual answer + criterion → judgment → timely feedback
Answer + judgment + stopping point → one save → receipt
```

Continuing the lesson and maintaining records follow their own paths:

```text
Feelings and questions → permission → next block

Saved facts → recovery, time statistics, progress indexes
Related changes → relevant checks
Import, integrity investigation, release → full checks
```

Teacher titles are labeled as teaching arrangements and linked to the source's wording and role. A forward reference such as “discussed later” may receive a brief explanation without becoming an invented required chapter here.

Comprehension, feelings and permission to continue remain separate decisions. Mathematical feedback can be prompt. “Saved” requires a durable receipt. A failed or unknown save is reported separately, and a failed projection does not erase a successful commit. Broad diagnostics do not run indiscriminately after every answer.

## Practice and exams

Practice retains source order, teaching order, actual answers and images, frozen criteria and each review. Direction hints, references and full solutions have separate, problem-bound authorization. Assistance affects independence; an instructor's excessive help is not a learner error. Supplemental problems need opt-in and cannot become counterfeit source problems.

Exams use an independent bank, suitability checks, isolation, cooldown, frozen scoring and a separate ledger. Mistake retests distinguish independent success, assisted success and contamination. Earlier mistakes and their evidence remain available. One answer does not establish a habit.

## Save and close

Saving at any point does not pause or terminate an activity. Resume the same problem, wording and gate.

Closing first presents a complete review of completed and remaining work. You can say naturally, “Let's end here and leave the remaining examples for later”; the teacher records an incomplete closure. Saving or answering correctly does not close the activity. If the review changes, decide using the new version. Declining lets you continue, and reopening retains the previous closure. Ending an entire course is a separate decision.

## Plans, reflection and governance

A group owns its composition, calendar and thresholds; courses own learning progress. Only one group is active at a time. Switching groups does not close unrelated courses. A suggestion remains proposed or deferred until a real implementation reference supports adoption.

Thoughts retain the learner's words. Reflections and testable patterns link back to evidence and can be consumed in later activities. System issues support recurrence, reopening and verified fixes. Rules identify observable failure and an actual consumer. Prose agreements are distinguished from machine enforcement.

## Migration and recovery

Export a frozen exchange package, check original bytes, identities, references and source drift, then import into a new instance. Keep the original. Reports distinguish preservation, semantic conversion and recovery readiness. Unparsed material and conflicts remain visible.

Historical permissions, scans and judgments stay historical. They do not authorize a new session. If either side advances after migration, preserve both deltas and reconcile their last common state before rollback or cutover.

## Maintenance and delivery

Related changes select affected checks. The journal, object versions and necessary action preconditions are checked on commit. Full checks cover import, integrity concerns and release qualification. Derived views can be rebuilt and never replace original facts.

Public packages contain the runtime and generic protocol, excluding personal instances, books, private attachments and measurement conversations. Lite is a read-only inspection projection. OKF defaults to mechanism documents. A candidate, a reviewed candidate and a published release are distinct states.
