# 课程识别与课程组规则（位于 `main/50_playbook/`）

**保护级别**：playbook

> 起因：旧实例档案的“当前课程”缓存曾与课程组成员表冲突（planned 是否算“当前”无法裁决）。
> 本文件一次性解决课程识别的引用混乱，并固化课程组的运行规则。
> 与 t2ag.md 宪法冲突时以宪法为准；本文件条款由 doctor 强制。

## 一、课程生命周期与容量组合

### 1.1 课程生命周期（写入各 `progress.md` 头部）

```
planned（预划，只存在于课程 `progress.md` 或 planned group 的 `plan.md`）
  → ongoing（已经开始且尚未结束）
  → completed（完成标准已经闭合）
  → dropped（用户明确终止；保留原因）
```

课程生命周期与当前课程组彼此独立。课程不在当前组时仍可保持 `ongoing`；用户明确提出时可以临时推进，
但不自动获得当前组预算，也不因一次临时学习自动换组。

### 1.2 当前容量组合

当前 active 的 `main/30_group/<GID>/plan.md` 是用户确认的**重点执行组合**：成员课程获得时间预算、最低频率、里程碑和
项目约束承诺。组文件不是“所有仍在进行的课程”清单，也不是排他锁。

- 系统可依据实际时长、学习能力、启动失败、截止期、依赖和项目限制提出调整建议。
- 加入、移出或降频仍须用户确认；不得由 agent 自动换组。
- 当前容量状态从 active G 文件派生，不写回 `progress.md`：
  `focused_in_Gxx / queued_for_Gxx / unallocated`。
- 完整进度节点与自动保存规则见 `50_playbook/progress_tracking.md`。

## 二、课程识别的引用纪律（本次事故的修法）

1. **权威链只有一个 owner**：active group 的 `plan.md` 是当前容量组合唯一真相源；
   memory 的“当前状态指针”只是 `t2ag_state_refresh.py` 生成的恢复缓存，不得反向拥有成员或预算。
   - 换组仪式先写 group plan，再运行 state refresh。
   - memory 与 plan 冲突时，以 plan 为准并修复 GENERATED 指针。
2. **全库禁止枚举式当前容量清单**：学生档案、learning_path 人工正文、任何 .md 不得手写"当前课程：A、B、C"。
   需要引用时只写指针，且**不得硬编码组代码**：
   - ✅ `当前课程组：见 memory 指针（成员见对应组文件）`
   - ❌ `当前课程组：G01` （组代码副本，换组即腐烂）
   - ✅ `当前课程：IV1001（见组文件）`（单课引用带指针，合法）
3. `main/10_student/profile/learning_path.md` 的课程生命周期和容量状态是机器生成缓存：
   - 生命周期取自各课程 `progress.md`。
   - 容量状态取自当前 active G 文件和 planned G 文件。
   - 由 `70_tools/t2ag_state_refresh.py` 统一刷新；生成区块禁止手写。
4. **定律入档**（problemlog 永久条目）：凡手写两遍的信息必然不一致——进度、版本号、课程清单已三次验证。解法恒为：删副本，留指针。

## 三、课程组的双线性质（设计意图，供组建档时参考）

每个组建议包含两类成员，配比随阶段流动：
- **项目线**（造外部的东西）：验收在世界一侧——能运行、有产出、可交付（如 PY1001+EG-0002）
- **语言线**（造内部的结构）：验收以卷面考核为主，过程指标为辅；题目只选编真题，不由 AI 生成。正文见 `main/50_playbook/exam_protocol.md`。

语言线默认期末权重：卷面 70%，过程指标 30%。卷面考核必须来自隔离的考核池；过程指标可含 mistake_bank 复发率、反例即答、盲判等。
组文件成员表加一列「线别：项目/语言」，期末评估分别按各自标准验收，不得互相折算。

### 项目线验证条款

> 项目线课程每个里程碑必须绑定验证模式（A/B/B-K，建组或 M 启动前登记，大调整窗口可改未启动 M），任何模式必须满足三机制：外部真相源、独立性测量、失败留痕。
> 操作细则见 `50_playbook/project_verification.md`。

## 四、刚性与流动的边界（组运行规则）

> **执行参数化原则**：协议层只规定必须存在的机制，不固定参数值。周期结构、复盘位置、小调整频率、大调整频率等参数，在建组仪式或学生执行参数中生成；未讨论前使用下述协议默认值。
>
> **协议默认调整规则**：3-1-3 周期；每循环两次小调整（每次至多一处运行参数），每三个循环一次大调整窗口。

| 维度 | 规则 |
|---|---|
| 周期 | **刚性**。执行参数必须写明周期容器；期末节点不后移，滑期进缓冲或大调整窗口消化 |
| 频率红线 | **刚性**。破线周期计入期末评估，连续两周期破线触发紧急复盘 |
| 仪式 | **刚性**。复盘、调整、卷面考核、组级评估、结组仪式不可省略；具体频率由学生执行参数决定 |
| 范围 | **弹性**。可砍内容进下一组，砍必留痕（progress 记"未完成部分及去向"） |
| 配方 | **组间流动，组内冻结**。成员增删、换教材、课程状态转正只在结组仪式发生；组内只走小调整/大调整分级通道 |

> **调整分级边界**：小调整 = 运行参数；大调整 = 范围级；配方级 = 组成员/教材/课程生命周期，只在结组仪式或用户明确发起的容量重组中发生。
> 机械判断：凡是需要动组文件成员表或 progress 生命周期字段的调整，至少是大调整；凡是要加减课程或换教材，就是配方级。
>
> 原理：deadline 固定、范围弹性 = 完成率的全部秘密；组内换配方 = 学习版的"阴跌中失耐心离场"。
> 第一个完整闭环的叙事价值 > 组内任何具体内容——完成本身是对旧病史的证伪。

## 五、换组仪式

执行正文见 `main/50_playbook/group_transition.md`；本文件只保留课程组规则与边界。

## 六、doctor 增检六条

| 检查 | 级别 |
|---|---|
| memory 指针指向的组文件不存在或状态非 active | FAIL |
| 全库 active 组数量 ≠ 1 | FAIL |
| active 组成员课程缺 `progress.md`，或生命周期为 planned/completed/dropped | FAIL |
| 组外 ongoing 课程被临时学习 | PASS；不自动改组 |
| 实际学习长期偏离容量组合 | WARN；建议复盘，不自动换组 |
| 权威链外的 .md 出现枚举式课程清单 | WARN |
| 考核池卷的题号引用出现在 lesson/practice 文件 | FAIL |
| `papers/` 下有卷夹但 index 未登记，或 meta 缺列/缺解答页码 | WARN |

> 第四条实现口径：
> - **只抓枚举，单课引用合法**：匹配"当前课程"后同一行出现 **≥2 个课程代码**模式（`[A-Z]{2,}\d{3,}` 计数），单代码不触发。
> - **白名单**：active/planned group 的 `plan.md`（真相源本源）豁免，不被此条打扰。
> - 单课引用如 `当前课程：IV1001（见组文件）`不违规；若该课不在当前组成员表内，doctor 顺手送一条 WARN "引用过时"。
