# 新增课程初始化流程

> 本文件是 T2AG「技能固化」文档之一。
> 当学生要学新课程时，按本流程完成课程文件夹、教学方案、教材资料、lesson 结构的初始化。
>
> **适用场景**：学生在对话中提出「我想学 XXX」「新增一门课 XXX」时触发。
>
> **关联文件**：
> - 规则定义：`main/t2ag.md` →「main/10_case/ 文件夹初始化规则」「course_status.md 的作用」
> - 课程列表：`main/10_case/course_info.md` →「课程列表」「添加新课程」
> - 变更历史：`main/00_core/t2ag_changelog.md`
> - 学生状态档案：`main/00_core/t2ag_emo.md` + 当前学生 `main/10_case/students/Sxxx/`

---

## 一、触发条件

满足以下任一条件，即触发新增课程初始化流程：

1. **学生明确要学新课程**：学生说「我想学 XXX」「新增一门课 XXX」「我要学数据结构」等。
2. **教学方案需要新增课程**：根据培养方案树形图，学生需要开始一门尚未创建的课程。
3. **课程列表中不存在该课程**：`main/10_case/course_info.md` 的「课程列表」表中没有该课程代码。

> **不触发的情况**：课程已存在（已在课程列表中），只是继续学习，此时走「跨会话恢复课程上下文流程」（见 `lesson_recover.md`）。

---

## 二、完整步骤

### 步骤 1：在 course_info.md 课程列表新增行

打开 `main/10_case/course_info.md`，在「课程列表」表中新增一行：

| 课程代码 | 课程名称 | 路径 | 当前进度 | 恢复关键词 |
|---|---|---|---|---|
| [课程代码] | [课程名称] | `main/[课程代码]_[课程英文名]/` | 未开始 | 读取 main/[课程代码]_[课程英文名]/course_status.md |

**示例**（以 MATH1607H 为例）：

| 课程代码 | 课程名称 | 路径 | 当前进度 | 恢复关键词 |
|---|---|---|---|---|
| MATH1607H | 数学分析（荣誉）I | `main/30_courses/MATH1607H_MathematicalAnalysis/` | 未开始 | 读取 main/30_courses/MATH1607H_MathematicalAnalysis/course_status.md |

> **字段说明**：
> - **课程代码**：学校官方课程编号（如 MATH1607H、CS1953）
> - **课程名称**：中文课程名称
> - **路径**：课程文件夹相对路径
> - **当前进度**：初始为「未开始」，后续随教学更新
> - **恢复关键词**：用于「继续学 XXX」时快速定位的路径

### 步骤 2：创建课程文件夹 `[代码]_[英文名]/`

在 `main/` 下创建课程文件夹，命名格式为 `[课程代码]_[课程英文名称]/`。

**示例**：
```
main/30_courses/MATH1607H_MathematicalAnalysis/
main/30_courses/CS1953_CppProgramming/
```

> **命名规范**：
> - 课程代码保留原样（含字母、数字、H 等后缀）
> - 英文名使用 PascalCase（每个单词首字母大写），不含空格
> - 文件夹名中避免特殊符号，防止编码问题

### 步骤 3：创建 course_status.md（教学方案 + 知识树形图 + 课时估算）

在课程文件夹中创建 `course_status.md`，从上到下包含以下结构：

> **权威链规则**：`course_status.md` 是该课程进度唯一真相源；`main/00_core/t2ag_memory.md` 与 `main/10_case/course_info.md` 的进度只作为缓存，由结课仪式刷新。

#### 内容结构

1. **课程描述与教学方案**
   - 课程基本信息（课程代码、名称、学分、开设学期、面向对象、教材）
   - 课程目标
   - 教学原则
   - 知识树形图（层次、重点）
   - 各阶段/各章节的**预计学习时长，以小时为单位**
   - 与本教学方案中其他课程的关联
   - 学生学习需求与学习倾向
   - 师生协商后的教学策略与讨论结果
   - **教学方案推荐的参考书目（含来源 URL）**

2. **当前进度**
   - 状态：未开始
   - 正在学：（空）
   - 已完成：无
   - 已投入学习时长（小时）：0
   - 下一步计划

3. **教学记录**
   - 初始为空，每次教学后追加

4. **已掌握知识点**
   - 初始为空

5. **常用命令**
   - 记录该课程的常用命令（如打开教材、OCR 命令等）

同时创建同级 `mistake_bank.md`，用于保存该课程知识性错误与复测记录。工具/环境问题仍写入 `main/00_core/t2ag_problemlog.md`。

#### 课时估算原则（重点）

> **学习时长估算必须遵循以下原则，不得凭空编造：**

1. **基于教材实际内容**：必须基于对教材目录、章节篇幅、定理/定义数量、例题与习题难度的实际阅读或检索。
2. **标注为「初步估算」**：所有估算结果明确标注为「初步估算」，并在实际教学过程中根据学生真实进度不断修正。
3. **参考因素**：
   - 页数
   - 定理/定义数量
   - 典型例题数量
   - 课后习题量
   - 学生已有基础
4. **lesson 划分原则**：先通读章节内容并划定学时，再按约 **2 小时 = 1 个 lesson** 拆分；具体边界根据内容连贯性调整，不必 rigidly 按小节编号。
5. **由大到小制定计划**：先确定课程总学时，再分到各章，再分到各节，最后拆分为 lessons。

**估算方法示例**（参考 MATH1607H）：
1. 以目标学校（如复旦大学）对应教材的教学大纲学时为参考基准
2. 按学生所在学校（如上海交通大学）该课程总学时进行比例缩放
3. 考虑课前预习、课后复习、做作业与订正，总学习时长在课堂学时基础上增加约 20%–50%
4. 按 2 小时 = 1 个 lesson 拆分

> **不得凭空编造**：若无法获取参考学时，应明确说明估算依据的局限性，并在教学过程中尽快修正。

#### 教学方案调研

> **制定教学方案时，应主动检索并参考当地前 2% 学校的教学大纲、课程安排、评价标准与培养方案：**

1. **优先使用学生所在学校的公开资料**：如学生所在学校已有公开教学大纲、培养方案，优先使用。
2. **参考同地区顶尖高校**：若学生所在学校无公开资料，参考同地区前 2% 学校的对应课程大纲。
3. **交叉验证**：多所学校的大纲交叉比对，取合理区间。
4. **记录来源**：教学方案中注明参考的学校、大纲来源 URL。

**调研示例**：
- 上海交通大学 MATH1607H：参考致远学院教师主页课程信息（学分、学时）
- 复旦大学《数学分析》教学大纲：参考对应教材的学时安排
- 上海交通大学《C++程序设计》课程教学大纲：参考课程编号 CS032 的官方信息

### 步骤 4：创建 `[缩写]_book/`

在课程文件夹中创建教材存放目录，命名格式为 `[课程缩写]_book/`。

**示例**：
```
main/30_courses/MATH1607H_MathematicalAnalysis/MATH1607H_book/
main/30_courses/CS1953_CppProgramming/CS1953_book/
```

> **用途**：存放该课程的参考书目（PDF、Text PDF、EPUB 等）。
>
> **下载规则**：参考 `main/t2ag.md` →「书籍下载规则」。数学/物理教材默认同时下载 PDF + Text PDF；下载前先检查是否已存在同名或同格式文件，避免重复下载。
>
> **命名规范**：尽量保留原文件名，包含书名、作者、版本信息；路径中不要有特殊符号。

### 步骤 5：创建 lessonXX/ 结构

当开始第一节课时，创建 `lessonXX/` 文件夹及内部完整结构：

```
[课程代码]_[课程英文名]/
├── lesson01/
│   ├── lesson01.md          ← 课程笔记
│   ├── thinking.txt         ← 课堂灵感
│   ├── practice/
│   │   ├── p/               ← practice：课堂练习
│   │   ├── f/               ← free thought：随想
│   │   └── a/               ← after class：课后习题
│   ├── illustration/        ← 插图保存目录（课程期间持久保存）
│   └── temppage/            ← 当堂课临时页面工作区（课程结束时整目录删除）
│       └── temp_page.md     ← 教材原文缓存
├── course_status.md
├── mistake_bank.md
└── [缩写]_book/
```

**各文件/目录说明**：

| 文件/目录 | 作用 | 生命周期 |
|---|---|---|
| `lessonXX.md` | 该课的具体笔记、示例、问答 | 持久保存 |
| `mistake_bank.md` | 该课程知识性错误、复测记录和权重 | 持久保存 |
| `thinking.txt` | 课堂灵感、顿悟时刻 | 持久保存 |
| `practice/p/` | 课堂练习（`pXX-Y.txt`） | 持久保存 |
| `practice/f/` | 随想（`fXX-Y.txt`） | 持久保存 |
| `practice/a/` | 课后习题（`aXX-Y.txt`） | 持久保存 |
| `illustration/` | 教材插图（HTML/SVG + LaTeX/TikZ） | 持久保存 |
| `temppage/` | 当堂课教材原文缓存、OCR 脚本与结果 | 课程开始时生成，结束时删除 |

> **练习文件命名格式**：`[类型][课次]-[编号].txt`，如 `p1-1.txt`、`f1-1.txt`、`a1-1.txt`。
>
> **temppage/ 缓存机制**：每堂课开始时生成，课程结束时整目录删除。`temp_page.md` 持续累积当堂课所有讲授过的页面原文。

### 步骤 6：确保当前学生三文件档案存在并新增课程小节

确保 `main/00_core/t2ag_emo.md` 存在（学生状态索引），并确保当前学生的 `main/10_case/students/Sxxx/` 三文件存在。

- **索引位置**：`main/00_core/t2ag_emo.md`
- **学生档案位置**：`main/10_case/students/Sxxx/`
- **若索引不存在**：自动生成学生状态索引模板
- **若学生文件夹不存在**：按 `S001/` 模板创建 `basic_info.md`、`personality_baseline.md`、`course_reflections.md`
- **若新增课程**：在该学生 `course_reflections.md` 中新增课程小节和知识点树形图

**学生三文件结构**：
```markdown
basic_info.md
personality_baseline.md
course_reflections.md
```

**course_reflections.md 新课程段落结构**：
````markdown
### [课程代码] [课程名称]
#### 知识点树形图
```text
[课程名称]
└── [章节/lesson]
    └── [知识点]
```
#### 感想记录
（按时间升序排列）
````

> **触发词**：学生消息以 `感受：`、`心情：`、`feeling:`、`emo:` 或 `感想：` 开头时，视为情绪表达，自动记录。
>
> **自动归类**：课程知识点相关感想写入 `course_reflections.md`; 哲学/生活/元认知感悟写入 `personality_baseline.md`。

## 三、课时估算原则（详细）

> 本节是步骤 3 中课时估算的详细说明，单独列出以示重要。

### 核心原则

1. **必须基于教材实际内容**：基于对教材目录、章节篇幅、例题密度和习题难度的实际阅读或检索，**不得凭空编造**。
2. **标注为「初步估算」**：估算结果明确标注为「初步估算」，并在实际教学过程中根据学生真实进度不断修正。
3. **由大到小制定计划**：先确定课程总学时 → 再分到各章 → 再分到各节 → 最后拆分为 lessons。

### 参考因素

| 因素 | 说明 |
|---|---|
| 页数 | 章节总页数 |
| 定理/定义数量 | 概念密度 |
| 典型例题数量 | 例题讲解时间 |
| 课后习题量 | 练习与订正时间 |
| 学生已有基础 | 影响理解速度 |

### lesson 划分规则

- **基准**：约 **2 小时 = 1 个 lesson**
- **边界调整**：具体边界根据内容连贯性调整，不必 rigidly 按小节编号
- **先通读再拆分**：先通读章节内容并划定学时，再按 2 小时拆分

### 估算方法示例

以 MATH1607H 数学分析为例：

1. **参考复旦大学**《数学分析》教学大纲（陈纪修教材配套课程）：数学分析（I）96 学时
2. **按上海交通大学** MATH1607H 总学时 96–128 进行比例缩放
3. **计入自学时间**：课前预习、课后复习、做作业与订正，总学习时长在课堂学时基础上增加约 20%–50%
4. **按 2 小时 = 1 个 lesson 拆分**

> **局限性说明**：不同学校的课程结构、习题课安排、考试难度不同，缩放会引入误差；学生个体差异会导致实际用时偏离估算。

## 四、教学方案调研

> 本节是步骤 3 中教学方案调研的详细说明。

### 调研原则

制定教学方案时，应**主动检索并参考当地前 2% 学校的教学大纲、课程安排、评价标准与培养方案**：

1. **优先使用学生所在学校的公开资料**：如学生所在学校已有公开资料，优先使用。
2. **参考同地区顶尖高校**：否则参考同地区前 2% 学校的对应课程大纲。
3. **交叉验证**：多所学校的大纲交叉比对，取合理区间。

### 调研内容

- 课程目标与基本要求
- 知识点覆盖范围与深度
- 各章节学时安排
- 评价标准与考核方式
- 推荐教材与参考书目

### 调研记录

教学方案中应记录：
- 参考的学校名称
- 大纲来源 URL
- 参考学时与缩放比例
- 估算的局限性说明

### 教学方案调节

- 教学方案可讨论、可调节
- **若学生学习欲望不强，可适当降低难度、放慢进度、减少拓展内容，优先保证基础掌握**
- 学生或教师可随时询问「这门课预计还要多久」，应基于剩余小时数回答

## 五、注意事项

1. **课时估算不得凭空编造**：必须基于教材目录、章节篇幅、定理密度、例题与习题量的实际阅读或检索。无法获取参考学时时，应明确说明估算依据的局限性。
2. **教学方案需参考顶尖学校大纲**：制定教学方案时，主动检索并参考当地前 2% 学校的教学大纲，记录来源 URL。
3. **lesson 结构必须完整**：创建 `lessonXX/` 时，必须同时创建 `lessonXX.md`、`thinking.txt`、`practice/{p,f,a}/`、`illustration/`、`temppage/` 全部子目录。
4. **学生状态按学生文件夹归档**：不在课程文件夹内创建 t2ag_emo.md；统一使用 `main/00_core/t2ag_emo.md` 作为索引,实际记录写入当前学生的 `main/10_case/students/Sxxx/`。
5. **课程列表同步更新**：新增课程后，`course_info.md` 课程列表的「当前进度」列是缓存；每次结课先更新 `course_status.md` 真相源，再同步刷新此列。
6. **变更记录不可遗漏**：新增课程后，必须在 `t2ag_changelog.md` 中记录，便于追溯。
7. **参考书目含来源 URL**：教学方案中推荐的参考书目必须写入 `course_status.md`，并标注实际来源 URL。
8. **教材下载前查重**：下载教材前先检查 `[缩写]_book/` 中是否已存在同名或同格式文件，避免重复下载。
