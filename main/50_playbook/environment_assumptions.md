# 环境假设登记（environment_assumptions）

**保护级别**：playbook

> 本文件登记 T2AG 代码里**成立但没写在任何规则里**的宿主环境假设。这类假设不会让 doctor
> 变红，只会在换宿主、换沙箱、换模型时突然咬人一口，然后靠交接口耳相传传给下一个人。
>
> **本文件不是**：安装指南、依赖清单、故障排查手册。它只回答一个问题——「这条假设一旦
> 不成立，我会看到什么，以及我该做什么」。

---

## 一、这份登记要证明什么

登记的目的是让**环境假设可探测**，不是让环境变得正确。

因此每条 `EA-XXXX` 必须能被一个只读探测证伪。写不出探测方法的，不是环境假设，是愿望，
不进本表。

**探测只报事实，不自动修复。** 探测到 `.git` 不可 unlink 就报告，不得代为清理；探测到
`fitz` 缺失就报告，不得自动安装。理由是：自动修复会把「环境不对」变成「环境曾经不对但
现在看不出来了」，而接管方需要看得出来。

## 二、字段

| 字段 | 含义 |
|---|---|
| **断言** | 一句可证伪的陈述 |
| **依赖它的代码锚点** | 哪段代码在假设它成立（用内容锚点，不用行号） |
| **探测方法** | 可直接执行的只读命令或检查 |
| **探测失败时的正确反应** | 接管方该做什么、**不该**做什么 |
| **首次记录** | 日期 + 是哪次实际代价把它逼出来的 |

## 三、与 doctor 的关系

doctor 原子项 `runtime.environment` 实现本表中标注「已探测」的条目。等级约定：

- **INFO**：假设不成立但只影响部分能力，教学可继续；
- **WARN**：假设不成立且会导致写操作产生难以察觉的副作用。

本表条目多于 doctor 已实现的探测是正常的——先登记，再实现。反过来不允许：doctor 不得
探测本表未登记的假设。

## 四、登记条目

### EA-0001｜`activity_close` 的生产根路径是硬编码的

- **断言**：`activity_close.PRODUCTION_ROOT` 硬编码为 `C:\Users\MikeChen\T2AC\t2ag`。在其它
  路径下运行 apply 会要求 `T2AG_022_CLOSE_TEST=1`，而生产路径下的直接用户授权闸门在其它
  路径下**根本不生效**。
- **依赖它的代码锚点**：`grep -n "PRODUCTION_ROOT" main/70_tools/activity_close.py`
  （`root.resolve() == PRODUCTION_ROOT` 分支与 `T2AG_022_CLOSE_TEST` 分支）
- **探测方法**：比较 `activity_close.PRODUCTION_ROOT` 与当前 `ROOT.resolve()`。
- **探测失败时的正确反应**：知道当前环境下哪些授权闸门未生效，据此收缩动作范围。
  **绝不要为了让 apply 通过而设置 `T2AG_022_CLOSE_TEST=1`**——那个变量的用途是测试，
  用它绕过生产闸门等于把闸门删了。也不要改 `PRODUCTION_ROOT` 去迎合当前路径。
- **首次记录**：2026-08-07。此前每份交接都要反复用散文警告「绝不要设那个变量」，
  因为没有任何机械手段说出这件事。
- **doctor 状态**：已探测（`runtime.environment`，不等时报 INFO）

### EA-0002｜PyMuPDF (`fitz`) 只存在于 `.venv`

- **断言**：`fitz` 不是宿主 Python 的全局依赖。沙箱与裸 `python3` 环境没有它。
- **依赖它的代码锚点**：`grep -n "import fitz" main/70_tools/t2ag_source_pages.py`
  （PPI 反算路径，惰性导入）
- **探测方法**：`import fitz`。
- **探测失败时的正确反应**：知道 `source_pages prepare` 的 PPI 反算路径在本环境不可用，
  改在有 `.venv` 的宿主机执行。**不得自动 `pip install`**——沙箱装上了不代表宿主机装上了，
  而下一个人会误以为它一直都在。
- **首次记录**：2026-08-07。`source_pages prepare` 在沙箱直接失败，失败信息未指向环境假设。
- **doctor 状态**：已探测（`runtime.environment`，不可用时报 INFO 并指名受影响命令）
- **作用域限定（2026-08-07 补）**：本条只覆盖 **`fitz` 那一条路径**（`source_pages prepare`
  的 PPI 反算），**不等于「沙箱不能做 PDF 分析」**。沙箱实测可用：
  `pdfimages` / `pdffonts` / `pdftotext` / `pdftoppm` / `qpdf`（poppler-utils）、
  `pypdf`、`pdfplumber`、`PIL`、`numpy`、`pdflatex` / `xelatex`。
  `T2AG_LAYOUT_CRITICAL_CRITERION_REPORT_2026-08-07.md` 的全部 PDF 只读实测
  （字体、文本层、图像对象、页面尺寸）即在沙箱内完成，未用 `fitz`。
  **误把本条读成「PDF 相关一律上宿主机」会造成不必要的阻塞**——该误读已在
  该报告的 A1 环节实际发生过一次。

### EA-0003｜某些挂载环境可建文件但不能 unlink（**范围为整个挂载，不限于 `.git`**）

> **范围更正（2026-08-07 22:1x，实测）**：本条原表述为「可在 `.git` 下建文件但不能 unlink」，
> 会被读成「限制只在 `.git`」。实测**整个挂载都不可 unlink**：
> `T2AC/`、`T2AC/t2ag/main/`、`T2AC/t2ag/main/40_course/**`、`outputs/` 逐一 `touch` 后
> `rm` 均返回 `Operation not permitted`；只有 `/tmp` 可删。
>
> **由此推出的两条硬约束（此前未写明）**：
>
> 1. **沙箱内不存在「移动文件」这个动作。** `mv` = copy + unlink，后半段必失败。
>    任何「把 X 迁到 Y」的任务在本环境只能做成**复制**，旧位置的删除必须由用户在宿主机完成。
>    施工单若写「迁移」，执行方须改述为「复制 + 待宿主机删除」，不得声称已迁移。
> 2. **任何创建临时文件的探测都必须遵循固定名 + 封顶残留**（见本条末「探测自身的残留」）。
>    2026-08-07 一次裸 `touch/rm` 能力探测在挂载内留下 4 个 `.rmtest*`，执行方无法自清，
>    只能交由用户手动删除。**先例已存在于本条，未被遵循。**

- **断言**：部分挂载（本轮为 Cowork 沙箱对 Windows 目录的挂载）允许创建文件，
  但不允许删除**任何**文件。Git 的锁文件协议依赖「建了能删」，因此 `git commit` 会
  **看起来成功**却留下 `HEAD.lock`、`objects/maintenance.lock` 与 `tmp_obj_*`；
  同一限制也使普通文件的移动、清理、原地替换（先删后写）在本环境不可用。
- **依赖它的代码锚点**：不是某段 T2AG 代码，是 git 自身的锁协议。相关规则见
  `grep -n "提交" main/50_playbook/git_workflow.md`。
- **探测方法**：在 `.git/` 下创建一个临时文件再删除它。**该探测的结论适用于整个挂载**，
  不需要、也不应当在其它目录重复裸探测（重复探测只会制造删不掉的残留）。
- **探测失败时的正确反应**：**本环境不得执行任何 git 写操作**（commit / add / tag / gc），
  改在宿主机执行。已经遗留的锁文件由用户在宿主机手动删除——探测方**不得**代为清理，
  因为清理 `HEAD.lock` 在正常环境下是危险操作，不能让它变成常规动作。
- **首次记录**：2026-08-07。一次沙箱 `git commit` 遗留三类锁文件，`HEAD.lock` 会让宿主机
  下一次 ref 更新直接失败；代价是用户手动删三个文件。
- **doctor 状态**：已探测（`runtime.environment`，不可删时报 WARN）
- **探测自身的残留**：探测文件名固定为 `.git/.t2ag_env_probe`（**不带 PID**）。在本假设不成立的
  环境下该文件删不掉，若按运行次数命名就会每跑一次 doctor 多留一个——探测本身会变成病症。
  固定名把残留封顶为一个，且下次探测会先尝试删除它。该文件可安全删除。

### EA-0004｜WorkBuddy 宿主不支撑 startup 编队的并行多 Agent 假设

- **断言**：`startup_orchestration.md` §一 假设宿主能跑「一个 Main Conductor + 两个辅助
  Agent」的**并行**编队。WorkBuddy 宿主实际做不到真正的并行多 Agent——三个角色
  （Main / Runtime Sentinel / Context Prefetcher）退化为**单 Agent 顺序执行**。这条假设
  没写成任何规则里的宿主前提，只在 playbook 的编队描述里隐含。
- **依赖它的代码锚点**：不是某段 T2AG 代码，是 playbook 的编队叙述：
  `grep -n "两个辅助\|并行\|单 Agent 降级" main/50_playbook/startup_orchestration.md`
  （§一「目标与默认拓扑」的编队描述与降级条款）。
- **探测方法**：在宿主用 Agent 能力尝试**并发**派生一个只读子任务，观察是否真正并行
  成立并返回；或直接观察一次启动——若三角色都在同一个 agent loop 里先后串行完成，
  即编队没有落地。
- **探测失败时的正确反应**：走 playbook §一 明确允许的**单 Agent 降级**（「辅助 Agent
  能力不可用时允许单 Agent 降级；降级不改变任何安全或授权边界」）；**如实**在启动报告
  里写「单 Agent 顺序执行」，不得把顺序执行描述成「并行编队已跑完」；也不要为了造出
  并行假象去强行派生并发子 Agent。
- **首次记录**：2026-08-07。学生在启动复盘中指出「WorkBuddy 实际上没法进行多 agent
  操作」；本 session 启动事实上就是单 Agent 顺序跑完三角色，但开场报告把它描述成编队
  已并行执行，掩盖了无并行的事实——也让视觉扫描门的开销没有任何并发可遮蔽，全额落在
  关键路径上（见 P-0057 因素④、P-0056）。
- **doctor 状态**：未探测（新登记）。多 Agent 能力属宿主能力而非文件系统/环境事实，
  `runtime.environment` 暂未覆盖；探测方式见上，待实现。

### EA-0005｜宿主「已连接的文件夹」不等于「已挂载的文件夹」（挂载是惰性的）

- **断言**：Cowork 宿主在会话配置里声明为「已连接」的文件夹，**未必已经实际挂载**。
  声明面（会话配置列出的路径与其 `/sessions/<id>/mnt/<name>` 映射）与实际面
  （`/sessions/*/mnt/` 下真实存在的目录）可以不一致；某些文件夹要到被**显式请求**
  之后才 materialize。启动期的检查跑在 materialize 之前，看到的是实际面。
- **依赖它的代码锚点**：`grep -n "def resolve_external_peer_root" main/70_tools/t2ag_doctor.py`
  （按挂载基名回退解析对端仓 root；解析不到即报 FAIL）。凡是按挂载点定位**仓外**资源的
  代码都吃这条假设。
- **探测方法**：把会话配置声明的文件夹清单与 `ls -d /sessions/*/mnt/*/` 的实际结果比对；
  出现在前者而不在后者的，就是声明已连接但未挂载。
- **探测失败时的正确反应**：**先请求挂载，再判断对端状态**。挂上之后仍不可达，才谈得上
  对端搬家或消失。**绝不要**据「root 解析不出」就断定对端仓没了，更不得据此删除引用身份
  （`cross_repo_reference.md` §四：断链先修解析，不动引用身份）。也不要把提示路径改成
  当前环境能凑合解析的样子去迎合——`peer_root_hints` 是环境提示，不是引用身份。
- **首次记录**：2026-08-08。本会话启动时 `操作复盘系统` 已在声明清单内且映射已写明，
  但 `/sessions/*/mnt/` 下并不存在，`runtime.external_references` 因此报 2 FAIL；
  显式请求挂载后 FAIL 当场消失，实算 `01-宪法层/交易纪律.md` sha256 与 sidecar 绑定
  逐位相符——**绑定全程健康，红的是环境**。代价：一次误判方向的根因排查，以及一度
  认真考虑「对端接不通就删掉引用」（若执行会删掉一条完好的纪律权威绑定）。
- **doctor 状态**：未探测（新登记）。声明面在宿主会话配置里，不在仓内，T2AG 读不到，
  故无法自证；已改为在 `check_external_references` 的不可解析分支**打印当前挂载面**
  并指向本条，让读者自己一眼分辨。**等级仍为 FAIL**：对端整仓消失落的是同一分支，
  降级会把「对端全没了」变成一条可忽略的 WARN。
