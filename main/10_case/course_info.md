## 教师实例(overlay)机制

> **overlay 是什么**：`teacher_overlay.md` 是"当前正在上课的教师实例" = 教师模板(T00X.md) + 当前学生/课程的具体需求。
>
> **为什么要分模板和实例**：
> - **模板**(`teachers/T00X.md`)：教师原型,稳定不变,定义核心人格、行为准则、默认回复格式,**不含任何学生特定内容**
> - **实例**(`teacher_overlay.md`)：当前正在上课的教师,包含**课程-教师映射表** + 学生特定的覆盖项(句尾标记、调研原则、教学节奏、协商结果)
> - **合并方式**：启动时读 overlay → 按当前课程查找映射表 → 读对应模板 → overlay 覆盖项叠加 → 生效教师人格
>
> **课程-教师映射**：
> - overlay 支持按课程指向不同教师模板,不同课程用不同教学风格
> - 当前映射:CS1953 → T002(编程教师)、MATH1607H → T003(数学教师)、默认 → T001(姐姐型)
>
> **跨项目复用**：
> - **模板可复用**：`T00X.md` 是纯人格原型,可直接复制到另一个项目使用
> - **overlay 不可复用**：overlay 绑定当前学生和课程,换项目/换学生时需重新生成
> - **复用方式**：新项目中创建新的 overlay,指向复用的模板,填写新学生特定的覆盖项
>
> **操作规则**：
> - 换学生：改 overlay 的覆盖项,模板不动
> - 换教师风格：改 overlay 映射表中某课程的指向,换一个模板
> - 换课程：按映射表自动切换对应模板
> - 修改模板：影响所有使用该模板的 overlay 实例

## 通用教学要求（适用于所有课程）

- **教材阅读与上下文保留**：讲授当前页时，必须先阅读本页，再参考前一页和后两页（共涉及4页上下文），确保知识完整连贯。若感觉这4页仍不足够，可主动请求阅读更多页。当需要查看教材内容时，必须使用扫描、OCR 等工具实际读取教材 PDF 原文，不能依赖已有讲义、记忆或概括——"看教材原文"意味着真正去扫描、提取原文，而不是凭已有材料复述。
- **逐节确认，不得跳内容**：讲完当前页/当前节的全部内容后，必须停下来问学生「确认理解了？继续 / 再讲一遍 / 提问？」。在学生明确确认继续之前，不得跳到后续内容；即使学生问了后续相关问题，也只能回答该问题本身，不能提前展开尚未讲授的后续内容。
- **复杂过程必须分步展开**：每道证明题（数学）或复杂问题/算法（编程）先给出**思维树形图**或伪代码，再按逻辑链条逐步推导或逐步实现，不能一次性倾倒完整答案。
- **问答与灵感实时记入 lessonXX.md**：学生的每个问题、错误尝试、灵感想法，当场记入对应 lesson 文件的「问答记录」和「错误尝试记录」。
- **课程进度实时更新**：每次课后先更新对应课程 `course_status.md` 教学记录、累计学习时长和精确停顿点，再刷新本文件课程列表缓存。
- **定义与分类必须完整呈现**：当教材中出现分类定义（如"区间分为有限区间和无限区间"）时，必须完整呈现所有类别及总类概念，不得遗漏任何子类或上位概念。
- **教材插图生成与保存规则**：扫描教材过程中识别到图号（如"图1.1.1"）时，应尽可能根据上下文生成对应插图。
  - **格式**：每种插图同时生成两个版本——**HTML/SVG** 和 **LaTeX/TikZ 源码**。
  - **命名**：文件名必须与教材图号对应，格式为 `{章号}_{节号}_{图号}_{描述}`，例如教材中"图1.1.1"（第1章第1节第1个图）应命名为 `1_1_1_venn_diagram`（描述反映图的内容）。若教材图号格式不同（如"图1.2"），则相应调整为 `{章号}_{图号}_{描述}`。
  - **保存位置**：`lesson/illustration/` 子目录。HTML 文件直接放入，LaTeX/TikZ 源码文件以 `.tex` 后缀放入。不需要额外生成 PDF。
  - **展示**：生成后必须提供完整的文件路径，并尽可能通过本地 HTTP 服务或超链接方式让学生能直接查看。不能只生成文件而不提供访问方式。
- **temppage/ 缓存机制**：每堂课开始时在 lesson 文件夹内的 `temppage/` 子目录中生成。该目录是当堂课的**临时页面工作区**，**每节课开始时清理一次**，课程结束时整目录删除。
  - **内容**：`temp_page.md` 保留在 `temppage/` 根目录，作为教材原文缓存；扫描原图放 `pages/`，OCR 原始结果放 `raw_ocr/`，OCR/检查脚本放 `scripts/`。
  - **temp_page.md**：缓存当堂课扫描的教材原文，**持续累积，课程结束清除**。随着教学推进，不断追加新扫描页的内容，不做删除。一整节课下来，`temp_page.md` 包含所有讲授过的页面原文。课程结束后随 `temppage/` 目录一起删除。
  - **物理文件滚动窗口（OCR 原图、OCR 结果、扫描图等）**：
    - **基准窗口：4页**。常态下保留4页物理文件。
    - **可扩展至6页**：当内容连贯性需要时，可预加载新页而不立即删除旧页，使存在的页数最多达到6页。
    - **6页后的加载**：当存在页数达到6页后，继续加载新页时必须同步删除最旧的1页，保持存在的页数 = 6页。
    - **回退机制**：当阅读到窗口中从 newest 往 old 数第4页时，删除最旧的2页，回到4页基准窗口。
    - **示例**：基准P1-P4（4页）→ 预加载P5（不删除）→ P1-P5（5页）→ 预加载P6（不删除）→ P1-P6（6页，达到上限）→ 加载P7，删除P1 → P2-P7（6页）→ 阅读到P4（从newest往old数第4页），删除P2,P3 → P4-P7（4页，回到基准）。
  - **插图处理**：若 temp_page.md 中出现教材插图（如"图1.1.1"），按「教材插图生成与保存规则」生成对应 LaTeX/TikZ 和 HTML/SVG 文件，保存进 lesson 文件夹的 `illustration/` 子目录中。
- **OCR 工具选择与结果校对**：
  - **工具选择**：教材扫描推荐使用 **PaddleOCR**（开源，本地运行）或 **Pix2Text**（专门识别数学公式）替代 Tesseract，对中文和数学符号识别效果更优。若网络可用，**MathPix API** 为数学公式识别效果最佳方案。
  - **结果校对**：OCR 结果必须进行人工校对，尤其是数学公式、花括号、下标、并集符号、无穷符号等。建立常见错误对照表：
    - `A`/`B`/`C` → 可能被误识别为 `4`/`8`/`(` 等
    - `∪`（并集）→ 可能被误识别为 `U`/`J`
    - `∞`（无穷）→ 可能被误识别为 `o`/`ce`/`8`
    - `∈`（属于）→ 可能被误识别为 `s`/`e`
    - `⊂`/`⊃` → 可能被误识别为 `C`/`D`
    - 下标 `x_{ij}` → 可能被误识别为中文乱码或遗漏
    - 花括号 `{}` → 可能被误识别为竖线 `|` 或遗漏
  - **校对流程**：OCR 结果需逐行对照扫描原图进行校对，数学公式部分必须逐符号核对。校对后的正确文本写入 `temp_page.md`，原始 OCR 结果保留在 `page_XX_raw.txt` 中备查。
> 此规则为所有课程的通用要求，优先于任何具体课程的差异化规则。

## 课程差异化教学要求

不同课程有不同的教学重点和特殊规则。在课程列表下方列出各课程的差异化要求，教学时必须查阅并遵循。

### MATH1607H 数学分析（荣誉）I —— 特殊教学要求

- **数学定义必须完整展示**：每个新概念、定理、引理必须给出严格定义，不能只给直观解释或简化版本。
- **数学语言训练优先**：强调符号使用（∈、⊂、∪、∩、∀、∃、⇒、⇔ 等），要求学生能用集合语言和 ε-δ 语言严格表述。
- **教材原文优先**：概念讲解优先引用陈纪修教材原文（含历史背景、严格定义），再补充解释。
- **证明思维树形图**：每道证明题先给出**思维树形图**，再按逻辑链条逐步推导，不能一次性倾倒完整证明。

### CS1953 程序设计(A类) —— 特殊教学要求

- **概念必须配合可运行代码**：每个语法概念、控制结构、函数或类，讲解时必须给出完整可编译运行的代码示例，不能只给文字描述或伪代码。
- **调试与错误分析训练优先**：遇到编译错误、运行时错误、逻辑错误时，引导学生阅读编译器/运行时的错误信息，定位问题行号，分析原因，逐步修正。不能跳过错误分析直接给出正确答案。
- **代码风格与规范训练**：从第 1 课起强调命名规范（驼峰/下划线）、缩进、注释、代码可读性。每段代码都应作为风格范例。
- **伪代码/思维树形图分步展开**：每道复杂编程题或算法题，先给出伪代码或思维树形图，再按步骤逐步实现，不能一次性倾倒完整代码。


### PY1001 Python 与茧房程序 —— 特殊教学要求

- **项目即课程主线**：以「制造茧房」个人信息过滤器为唯一实践载体学习 Python，禁止脱离项目单独堆语法。
- **跟项目走、教材当字典**：PY1001 以 `main/30_courses/PY1001_PythonCocoon/cocoon_plan.md` 的 M0-M6 为教学大纲；《Python编程：从入门到实践》第3版 / Python Crash Course 3e 是主教材来源，不按页码逐页推进。
- **教材原文缓存约束行动**：每个里程碑开始前，必须从主教材、辅助资料或官方文档抽取当前所需原文进 `lessonXX/temppage/temp_page.md`，讲完马上写 Cocoon 真代码，不能凭模型记忆讲。
- **本课跳过例外**：与当前里程碑无关的章节（游戏、GUI、Django、部署等）可整块跳过并记录到 `course_status.md`；这不算违反通用“不跳内容”规则。
- **每课必须有可运行产物**：每个 lesson 至少推进一个真实文件、函数、测试或命令，形成可积累的 cocoon 程序。
- **AI 只给骨架和 review**：教师可以解释、拆步骤、给最小例子和审查代码，但关键函数体由学生自己写。
- **报错训练优先**：学生先自读 traceback 3 分钟并猜测原因，再由教师引导定位；知识性错误写入 `main/30_courses/PY1001_PythonCocoon/mistake_bank.md`。
- **与数分双线互养**：Python 作为即时正反馈出口，数分训练的反例意识迁移到测试用例和边界条件。
- **走私槽不可删除**：M5 日报必须保留随机低分内容，防止信息过滤器过拟合旧偏好。

### IV1001 投资与量化基础 —— 特殊教学要求

- **不提供个股建议**：agent 不得回答“该不该买/卖某只股票”，只能检查论点、流程、风险、数据来源、日志完整性和回测方法。
- **证伪与止损分离**：证伪条件必须是基本面或结构事实；“跌了 10%”不算证伪，只算止损。
- **交易日志优先**：下单前必须写 `main/40_practices/trading/trade_journal.md` 的论点、证伪条件和止损位；课程案例优先来自真实日志。
- **回测审计优先**：所有策略结论必须检查过拟合、前视偏差、幸存者偏差。
- **实盘接口后置**：纸面系统未经 3 个月跟踪验证前，不接 QMT/miniQMT/PTrade 等实盘自动化接口。
- **G01 不开课**：IV1001 当前为 planned，不占用 G01 每日 4h 学习预算。

## 添加新课程

1. 在「课程列表」表中新增一行，填写课程代码、名称、路径、初始进度缓存
2. 创建课程文件夹：`[课程代码]_[课程英文名称]/`
3. 在课程文件夹中创建：
   - `course_status.md`（课程状态与教学方案）
   - `mistake_bank.md`（该课程知识错题库）
   - `[课程缩写]_book/`（存放参考书目）

   - `lessonXX.md`（课程笔记）
   - `thinking.txt`（课堂灵感）
   - `practice/p/`、`practice/f/`、`practice/a/`（练习目录）
