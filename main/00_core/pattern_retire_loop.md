# 复利回路模式（Retire-Loop Pattern）

> T2AG 第一个正式设计模式。凡"记录→归因→复测→退役"结构的文件皆为本模式实例。
> **命名法则：模式定义一次于此，实例保留领域名**（trade_journal 不改叫 mistake_bank_trading）。
> 新域需要此能力时：按参数表实例化 + 领域名命名 + 头部声明，**禁止**复制粘贴另一实例再改。

## 模式定义（五要素，实例化时逐项填参）

| 要素 | 含义 | 约束 |
|---|---|---|
| ①记录对象 | 记什么 | 单一域，越界内容按边界规则转投 |
| ②写入时机 | 事前存证型 / 事后归因型 | 事前型多"预测栏"（论点/止损），事后型多"根因栏" |
| ③归因层 | 根因必须指向哪一层 | 概念层/规则层/流程层——禁止外因（运气/操控/模型抽风） |
| ④消费方 | 谁在何时读它并改变什么 | 有且只有一个（边界规则裁判决歧义） |
| ⑤退役条件 | 何时停止复测 | 权重归零 / 同标签连续 N 周期未犯 |

## 演化预留

未来新域（写作实践、健身课…）需要复利回路时：在登记表加一行 + 按模板实例化。
若某天实例超过 6 个且参数高度雷同，再考虑抽象成统一格式+脚本化复测——**在那之前，
四个手写实例的维护成本低于一个通用框架**（不要提前工程化，这是 T2AG 一贯哲学）。
