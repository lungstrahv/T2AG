01 / Preface

一个伴学生共同成长的本地学习系统

T2AG 把可更换的 AI agent 接到一组学生主导、可以直接阅读和修改的本地文件上。它保存连续性，但不预先替学生决定完整形态。

本地记忆

课程进度、学生体验、错误、方法和下一步都留在可检查的文件里。换一个 agent，学习不必从自我介绍重新开始。

学生主导

学生对文件和规则拥有最终决定权，可以根据学习体验对系统内容进行生成、修改与重新组织，而不是被一个固定的学习框架束缚。

使用中成长

初装只提供最小可运行结构，课程、技能、工具和偏好在真实使用中逐步形成。学生提出需求后，系统可以立即改造文件、生成展现形式或工具；使用后的反馈又会继续修正它，让系统越来越贴近学生需求，也让学生对工具形成更清楚、更从容的掌控感。

02 / Principles

设计围绕学生，而不是围绕文件

文件只是可改造的器具。系统的价值是把学生的需求迅速变成可试用的改变，再让有效改变留下来，减少以后重复说明和重复忍受。

01

说出需求或不适

可以谈目标、卡点、阅读体验、情绪、节奏，也可以直接说“这个文件不好用”或“我想换一种学法”。

02

当场生成与改造

Agent 可以换一种或加一种展现形式，修改课程文件，生成图、交互页、小工具、检查脚本或技能原型。

03

真实使用并反馈

学生不必先设计完整方案，只需使用后说明哪里更顺、哪里仍烦、哪里误解，Agent 据此继续调整。

04

固化或撤回

一次性产物留在 lesson；稳定偏好写入学生档案；成熟流程才固化为 playbook 或 tool。不好用的改变可以撤回。

你可以直接这样说

  • “换一种或者加一种展现形式。”
  • “把这个步骤做成以后能复用的技能。”
  • “这个文件让我很费劲，改造一下。”
  • “先做一个小工具，我用完再给反馈。”

摩擦如何被真正减少

反馈不会只停在对话里。课程内偏好进入 course_reflections.md，跨课程稳定偏好进入 basic_info.md，解题方式进入 reasoning_patterns.md，重复流程按门槛进入 50_playbook/，确定性检查进入 70_tools/。学生始终拥有修改、拒绝和撤回这些文件的 root 权限。

03 / Start

把基础安装包变成自己的 T2AG

第一次使用只需要回答少量问题。系统会把空白结构变成你的学生档案、课程入口和下一步行动；以后回来时，不必重新解释自己和学习进度。

第一次打开时，你会经历什么

你拿到的是一个极简的基础安装包。把它复制为自己的 t2ag 文件夹，在 AI 环境中打开并发送“T2AG”，然后回答昵称、课程、教材、当前进度和学习偏好。确认信息后，你会看到自己的档案与课程生成、欢迎信息出现，并得到一条可以直接开始的下一步。此后文件会随着使用和反馈继续变化，最终成为更贴近你习惯的个人学习系统。

拿到基础安装包→复制为自己的 t2ag→回答 5 个问题→看到档案与课程生成→获得可直接执行的下一步→以后直接继续学

第一次使用

按问题告诉系统你是谁、要学什么、用什么教材、学到哪里和怎样学更舒服。系统复述确认后再创建内容，不替你猜测。

main/50_playbook/first_run.md

以后再回来

直接说“继续学某门课”即可恢复课程、教材位置、未解决问题和复测内容。新的课程、技能、工具与偏好仍可随时继续加入。

06 / Feedback

反馈持续调节下一步

系统不替学生定义一个固定“状况”。它把学生主动反馈、长期体验、学习结果和进度一致性当作参考，形成调整提案，学生确认后才执行。

学生主动反馈

学生此刻说出的目标、卡点、不适、兴趣和形式要求优先。系统先回应当前体验，而不是用档案覆盖本人陈述。

长期体验参考

basic_info.md、personality_baseline.md 和课程感想提供稳定偏好与历史摩擦，但只用于提出更合适的节奏、语气和形式。

学习结果参考

reasoning_patterns.md、疑问和知识点状态提供可观察证据，帮助决定该解释、练习、复测，还是换一种反馈方式。

进度一致性参考

权威链只校准“实际学到哪里”：course_status.md 是进度真相源，memory 与 course_info 是缓存，doctor 负责发现冲突。

参考不会直接变成处置。先形成可撤回的调整提案，再由学生确认，并用下一轮体验检验它是否真的降低了摩擦。

主动反馈+体验档案+学习结果+进度权威链→调整提案→学生确认→改教法 / 改文件→继续反馈

08 / Environment

环境默认保持安静

进入项目、上课和普通验收都不能成为下载理由。

默认动作

  • 复用现有解释器，不创建、删除、升级或重建 .venv。
  • 只检查 pyvenv.cfg、版本、直接依赖、pip check 与最小 smoke test。
  • 不递归枚举虚拟环境每个文件。

需要下载时

  • 先报告名称、用途、预计下载量、磁盘、缓存位置和耗时。
  • 用户明确授权后才执行。
  • 预计超出申报值 20% 或新增超过 500 MB 时停止并重新确认。
