# 首次启动

**保护级别**：playbook

> **呈现治理 owner**：本流程面向学生的措辞分界（Learner/Operator Surface）与停顿
> （Meaningful Pause）以 `progress_governance.md` 为裁决正本（EV-0034，PG-D0=A）；
> 本文件继续拥有首启流程正文。

首次启动只初始化一个学生实例，不创建学生编号层。

## 判据

- `10_student/profile/profile.md` 的 `initialization_status` 不是 `initialized`；或
- profile 仍含必填占位符；或
- memory 上次课摘要日期为 `—`。

## 生成入口

实例由 `main/70_tools/t2ag_init.py` 生成，不由模型照本文手抄文件：

```powershell
python -B main/70_tools/t2ag_init.py init --answers answers.json
python -B main/70_tools/t2ag_init.py new-course --course-id <ID> --name <名称> ... --date YYYY-MM-DD
python -B main/70_tools/t2ag_init.py new-group --group-id G01 --members <ID> --container-mode <progress|schedule> --date YYYY-MM-DD
python -B main/70_tools/t2ag_init.py activate-group --group-id G01 --date YYYY-MM-DD
```

组**只能生为 planned**（2026-08-22 用户裁决）：`active` 是建组仪式之后的状态，
`new-group` 不收它。仪式内容——议定 `calendar.md` 容量参数、progress 组把
`plan.md`「主干碑序列」的模板行替换为逐碑确认的真实碑行——发生在两条命令之间；
`activate-group` 只做公证：验真实碑行、数碑落锚 `keystone_total_frozen`、翻状态。
碑行仍是模板占位（`碑描述`）时它会拒绝执行——那不是刁难，是防「状态先出现、
判断没发生」（P-0077 同族）。

`answers.json` 只保存第 3 步中用户愿意提供的资料；五项均可省略，工具按公开 schema 补**运行
参数**，缺失的**学生事实**一律写 `not_provided`（呈现为“尚未提供”），不用默认档位冒充；
也不创建 `.venv`、不装依赖、不下教材、不生成 Engagement、不做 git 写入。
模型的职责是提问、把答案写成 `answers.json`、调用工具、复核输出，而不是发明 schema。

## 参考学习方案先行

首次启动的建课部分依次经过三层，顺序不得颠倒：

1. **规划条件**：先展示系统已经知道的条件，再邀请学生补充或修正需求。条件包括学习水平、
   想达到的结果、已有基础、可投入时间、现有材料和工具、使用工具的习惯、日程限制与辅导
   偏好。每一项只有三态：**已提供**（学生本人说过）、**尚未提供**（内部值 `not_provided`）、
   **公开假设**（系统为推进而先行假定，且已在方案里标明可改）。机器默认值只能充当运行
   参数，不得进入「已提供」，也不得被复述成学生事实。
2. **参考学习方案**：根据规划条件生成一份完整、可阅读、可修改的候选方案，并把正文直接
   展示给学生。方案至少包含目标、已知条件与假设、建议路线、时间安排、材料与工具用法、
   阶段产出、反馈方式和待确认问题。此时尚未创建 Course 或 Group，也不写学习进度。
3. **课程类型与推进方式**：只有方案正文已经展示之后，才判断课程属于 Mastery、Project
   还是 Praxis。若为 Mastery，再结合方案解释 `textbook / goal / project` 三种 Learning
   Mode、给出推荐及理由；Project/Praxis 直接采用类型内生推进协议，不再要求选择 driver。

三种 Mastery Learning Mode 回答“什么推动下一步”，使用下列学生可理解的解释：

- `textbook`：有明确主教材，主要按教材章节与页码推进；
- `goal`：以要获得的能力或结果为主线，资料按目标选择；
- `project`：以为掌握服务的可运行产物推进；完成仍由理解与确认门裁判。

Project Course 按 Project Plan 的下一开放 Goal/Milestone 推进；Praxis Course 按真实行动、
现实反馈和复盘推进。二者是课程类型，不是可选模式。完整规则见 `book_management.md` §三。

学习模式不是 `course_type`、Lesson/Exercise 入口、Group 结构或节奏码。模式解释之后仍不得
要求新用户理解或确认 `course_type`、`entry`、`group_id`、`G01`、`container_mode`、
`progress / schedule`、`cycle_structure`、`3-1-3`、教师模板 ID 等实现字段。特别禁止询问
“是否接受上一条列出的全部默认设置”或同义的整包确认。不得向 Project/Praxis 用户追问
driver，也不得把 Mastery 的 project-led mode 冒充 Project Course。

最终确认必须针对学生读过的参考学习方案及其学习模式，例如：“按上面的方案建立
《小说写作基础》，以目标模式推进；这些条件、路线和模式是否准确？”只有学生明确确认后，
才把方案映射进 Course 与 Group 原件。确认前的候选方案不得冒充已创建课程或 committed
Learning Path；确认后的权威状态仍由 Course、Group 与生成的 learning path 各自持有，
不另存一份会漂移的方案真相源。

## 用户可见状态与停顿

首次体验只有四个用户可见状态；内部命令和状态迁移不得制造第五个状态：

1. **了解你**：一次自然对话，回显已知条件并邀请一次性补充；语气是“帮助我为你定制”，
   不是“填写必填字段”。注册资料与规划条件属于同一次对话，不拆成两轮。
2. **给你看方案**：直接展示方案全文及公开假设；用户不需要打开文件才能审阅。
3. **一起定下来**：方案之后再解释学习模式，只确认会改变学习体验的条件、路线和模式。
4. **可以开始**：内部落盘和健康检查完成后，只说明准备结果与第一步。

全程只有两个用户停顿：

- **停顿 A｜补充条件**：第 3 步用**一次**自然对话同时覆盖可选注册资料与规划条件，问完等待；
  学生已经给够信息或明确让系统先拟方案时，立即结束该停顿。禁止拆成「注册问卷」与
  「规划问答」两轮阻断——它们合并为这一个停顿，第 5 步不再开第二次提问。
- **停顿 B｜审阅方案**：第 6 步完整展示方案和模式后等待确认或修改。

学生通过停顿 B 后，`new-course → new-group → 方案映射 → activate-group → refresh →
doctor` 是一段无停顿的内部落盘。不得把命令成功回执、planned/active 迁移或 Doctor 警告
转换成新的用户确认门。完成呈现同样不构成第三个停顿：回执直接给出第一件事并就地开始，
不再另设“是否现在开始”的确认门，也不主动询问是否删除发行源。

### 面向学生的标准回应骨架

停顿 A 采用自然语言回显，不展示字段名；它是首次启动里唯一的一次资料征询，注册资料与
规划条件写在同一段话里：

> 我会先为你起草一份可以直接阅读和修改的参考学习方案。关于你，我这边现在还是空白——
> 你想学什么、希望最终能做到什么、目前大概到哪一步、每周大约能投入多少时间、手边有哪些
> 书或软件、习惯用纸笔还是电脑、希望我怎样称呼你、希望怎样收到反馈，你愿意说多少就说
> 多少。不确定或不想说的都可以跳过，我会把它明确写成方案里的假设，而不是替你填一个数字。

停顿 B 的方案至少使用“你的目标 / 当前条件 / 建议路线 / 时间安排 / 材料与工具 / 阶段产出 /
反馈方式 / 方案假设”这些自然语言栏目。方案正文结束后才解释学习模式，最后只问：

> 按这份方案建立《小说写作基础》，并以目标模式推进，是否符合你的想法？需要修改的地方
> 直接告诉我即可。

一份合格的方案正文示例（内容按学生条件变化，不照抄数值；示例中的条件全部来自学生在
停顿 A 的自述，未自述项一律进「方案假设」栏或写“尚未提供”）：

> **《小说写作基础》参考学习方案**
>
> **你的目标**：从零开始掌握小说构思与开篇写作，最终完成一份故事大纲和一个可继续修改的
> 开篇场景。
>
> **当前条件**：初中阶段；目前没有写作基础或明确方向；每周约 10 小时；工具习惯尚未提供。
>
> **建议路线**：先用短例子认识类型、主题、主角和冲突；再建立人物关系；接着完成故事主线
> 大纲；最后写出开篇并依据反馈修改。每一步都产生可阅读的作品，不以记住术语作为完成标准。
>
> **时间安排**：每周安排约 6—8 小时学习与写作、2—4 小时阅读和修改；具体分到哪几天由你
> 决定，忙碌时可以缩短单次学习，不需要补“欠下的课”。
>
> **材料与工具**：初期使用系统提供的短篇示例和写作模板；纸笔、Word 或其他熟悉的写作工具
> 都可以。在你说明习惯前，方案不强制指定软件或购买教材。
>
> **阶段产出**：①一页故事设想；②人物与关系卡；③故事主线大纲；④开篇场景初稿与一次修改。
>
> **反馈方式**：每次先指出作品已经成立的部分，再聚焦一个最值得改进的问题，给出可直接尝试
> 的修改方向；是否需要更细的示范由你决定。
>
> **方案假设**：暂按中文小说、从短篇或长篇开篇切入；偏好的题材、写作工具和反馈力度尚未提供，
> 随时可以调整。

紧接方案正文再说明：“这是一门 Mastery 课程，方案推荐**目标模式**，因为推进依据是你逐步
获得构思和写作能力，而不是读完一本固定教材。教材模式按书推进；项目式模式用作品促进掌握，
但完成仍看能力确认。若目标本身是交付一个由外部机制验收的成品，则应建立 Project Course；
若目标依赖真实发布和读者反馈，则应建立 Praxis Course。”不得把类型/模式解释提前成注册问卷。

禁止在停顿 A 与停顿 B 之间先宣称“课程已建立”，也禁止用“全部同意”“同意激活”作为推荐
回复格式；学生用自然语言表达同意或修改即可。

## 步骤

1. 按 `50_playbook/startup_orchestration.md` §零展示当前发行版的 `welcome_msg`、
   active `art_file` 字符画与版本号。
2. 运行 doctor，确认 Skeleton 结构有效且没有真实实例。
3. **停顿 A**：用一次自然对话同时覆盖可选注册资料与规划条件，不得拆成一长串阻断问答，
   也不得追加学校、年级、专业、Agent 数量或提示闸门问题。同一次提问里一并邀请：
   - 称呼（自由文本）；
   - 学习水平（参考说法：`中学在读 / 大学在读 / 学士`）；
   - 是否引入参考培养方案（参考说法：`是 / 否`）；
   - 学习兴趣（自由文本）；
   - 自我介绍（自由文本）；
   - 想学什么、希望最终能做到什么，以及已有基础和接触过的材料；
   - 每周可投入时间、通常可学习的日期和必要休息；
   - 能使用的书籍、软件、设备或其他工具，以及使用这些工具的习惯；
   - 其他限制、风险、偏好或特殊需求。
   若任务预计包含多块长篇讲解，同一组问题里还可选问是否偏好“先地图、后逐支”，以及
   学生希望怎样确认后再继续；未回答时只在方案中标成假设，不增加一次阻断确认。
   全部可跳过；空回复不得继续追问，也不得回到本步补问。学生本人说过的进「已提供」；
   没说过的写 `not_provided`（呈现为“尚未提供”）或作为公开假设进入候选方案。
   **学习水平没有默认档位**——不填即 `not_provided`，不得默认成中学在读；`同学` 只是称呼
   fallback，`有待生成` 只是「还没生成」的标记，二者都不是学生自述。内部值与字段形状见
   `main/70_tools/answers.schema.json`；`answers.example.json` 只展示五项真实形状，带
   `example_only: true`，工具必须拒绝直接消费。启动协作、结课记录、长篇组织、提示闸门、
   时区和 cutoff 全部使用 schema 默认**运行参数**（它们是机器如何运行，不是学生是谁），
   用户日后可在 profile 中修改。讲解语言不在本步询问：安装阶段的无默认语言选择已经决定
   Edition，中文版模板为 `zh-CN`，英文版模板为 `en-US`，`init` 只保留该值。
4. 运行 `t2ag_init.py init`（对应本步与第 10 步）。它将 profile 从模板改为
   `initialization_status: initialized`，并写入
   `agent_collaboration_preferences.v1`、`agent_pool_limit`、`agent_max_active`、`agent_parallel_startup`、
   `agent_startup_readiness`、`agent_background_reporting`、
   `activity_close_preferences.v1`、五项全局结课偏好、学习时区/cutoff、
   `activity_close_preferences_initialized_at`。首次结课提示 marker 初始化为
   `pending` / `none`；真正展示一次后才原子改为 `shown` / 带时区时间。
5. 告诉学生：“我会根据你提供的需求和已有条件，先起草一份可阅读的参考学习方案；确认
   方案之前不会创建课程。”随后把停顿 A 收到的条件回显一遍，并标出哪些仍是公开假设。
   **本步不再开第二次阻断提问**：停顿 A 问过的内容不重复索取；学生只回答了一部分时，
   未答项直接作为公开假设或“尚未提供”进入候选方案，不追问到填满字段。学生在回显后
   自发更正条件的，就地采纳并继续起草，不因此新增一次确认门。
6. 生成并完整展示参考学习方案正文，先让学生读到目标、条件、路线、节奏、资源、产出、
   反馈和假设；不得只给文件路径、摘要或“方案已创建”的宣称。方案正文之后，先解释课程
   类型；仅当判为 Mastery 时再解释三种 Learning Mode，说明推荐理由与改选影响。最后询问学生
   要修正哪些条件或路线，以及是否确认该方案、类型与（如适用）模式。必须等待学生回应；本步不运行
   `new-course`、`new-group` 或任何课程状态写入。
7. 学生明确确认参考学习方案、课程类型与适用的 Mastery Learning Mode 后，才确认马上要做的第一件事，使用“从第一小节
   开始学习”或“先做一道题看看水平”等自然语言；模型在内部映射为 `course_type`、可选 `learning_mode`
   与 `lesson | exercise`。用 `t2ag_init.py new-course` 按 `new_course_init.md` 创建 Course
   和首个学习活动。
8. 第一组在内部使用下一个合法 Group ID；首次只有一门课时，成员就是刚创建的课程，不再
   询问“首个课程组”或要求确认 `G01`。把已确认方案中的时间、休息和路线映射成预算、日历、
   容器与循环字段；不重复询问，`3-1-3` 等节奏码不展示。用 `t2ag_init.py new-group` 建立
   plan/calendar/review，并用 `bindings/_README.md` 持久化空 binding 域。只有学生明确同时
   建立多门课程时，才用自然语言确认先学哪一门，并在内部传给 `--current-course`。
   `new-group` 只生成 planned 组；随后把同一份已确认方案中的容量参数和真实里程碑写入
   calendar/plan，再运行 `activate-group` 公证激活。这里没有新的用户决定，禁止再次要求
   回复“同意激活”；只有映射时发现方案缺少会实质改变路线的信息，才回到第 6 步补方案。
9. 在 `20_teacher/overlay.md` 唯一的“课程—教师映射”表中建课程到教师模板的
   显式行；模板单元使用精确 `` `main/20_teacher/Tddd.md` `` 路径。
10. 完成发行身份切换，但不启动云同步：
   - 把 active skin 的 `art_file` 改为用户确认的个人实例字符画；未另选时使用
     `03_inori_2.txt`，不再保留 Skeleton 专用 `01_welcome.txt`；
   - 将 Cloud project mode 从 `generic_skeleton` 切为 `personal_instance`，在状态中
     明确 `new_cloud_sessions_allowed: false` 与
     `new_component_directives_allowed: false`，并让个人实例提示词携带
     `T2AG_SESSION_CLOSE / T2AG_CLOUD_CHANGE_DIRECTIVE / T2AG_CLOUD_HANDOFF`；
   - `cloud_bridge_status` 继续保持 `paused`，本步骤不授权任何云写回。
11. 更新课程 `progress.md` 的起点与下一动作。
12. 运行 state refresh `--write`，让 memory 的当前 group、课程、LearningActivity、教师与
   `learning_path.md` 同步生成；确认这些指针不再为 `—`。
13. 运行 state refresh `--check` 和 doctor，只有两者都通过才算首次启动完成。

## 完成呈现

首次启动完成后，面向学生的回执只呈现：课程名称、已确认的学习模式、方案中的关键条件，
以及**马上要做的第一件事本身**——直接给出并就地开始它，**不再另设“是否现在开始”的确认门**
（学生已在停顿 B 确认过方案与第一件事，再问一次不改变任何东西，属于答不出「不同回答会
改变什么」的停顿）。不得默认展示 Group ID、冻结碑数、route 状态、Doctor/Test 数量、
Cloud 状态、文件改动数或非阻断维护提示；这些是诊断回执，学生主动询问或出现阻断时再展开。

安装时复制出的**发行源默认保留**：本步不主动询问是否删除它，只在回执里用一句话说明它可以
稍后自行清理。只有学生自己提出要删除，才进入一次明确的破坏性确认。

推荐形态：

> 《小说写作基础》已经按你确认的参考学习方案准备好，将以目标模式推进。第一步是明确你
> 想写的小说类型、主角和核心冲突——先说说你脑子里已经有的画面、人物或一句话设定，哪怕
> 还很模糊；想换个开始方式随时告诉我。（安装用的发行源目录仍留在原处，不影响使用，你想
> 清理时随时可以删。）

不得自动创建 `.venv`、安装依赖、下载教材、生成真实 Engagement 或替用户选择课程。
