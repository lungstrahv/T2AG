# 课程识别与课程组规则（位于 `main/50_playbook/`）

**保护级别**：playbook

> 起因：旧实例档案的“当前课程”缓存曾与课程组成员表冲突（planned 是否算“当前”无法裁决）。
> 本文件一次性解决课程识别的引用混乱，并固化课程组的运行规则。
> 与 t2ag.md 宪法冲突时以宪法为准；本文件条款由 doctor 强制。

## 一、课程生命周期与容量组合

### 1.1 课程生命周期（写入各 `progress.md` 头部）

```
planned（预划，只存在于课程 `progress.md` 或 planned group 的 `plan.md`）
  → ongoing（已经开始且尚未结束）
  → completed（完成标准已经闭合）
  → dropped（用户明确终止；保留原因）
```

课程生命周期与当前课程组彼此独立。课程不在当前组时仍可保持 `ongoing`；用户明确提出时可以临时推进，
但不自动获得当前组预算，也不因一次临时学习自动换组。

### 1.2 当前容量组合

当前 active 的 `main/30_group/<GID>/plan.md` 是用户确认的**重点执行组合**：成员课程获得时间预算、最低频率、里程碑和
项目约束承诺。组文件不是“所有仍在进行的课程”清单，也不是排他锁。

- 系统可依据实际时长、学习能力、启动失败、截止期、依赖和项目限制提出调整建议。
- 加入、移出或降频仍须用户确认；不得由 agent 自动换组。
- 当前容量状态从 active G 文件派生，不写回 `progress.md`：
  `focused_in_Gxx / queued_for_Gxx / unallocated`。
- 完整进度节点与自动保存规则见 `50_playbook/progress_tracking.md`。

## 二、课程识别的引用纪律（本次事故的修法）

1. **权威链只有一个 owner**：active group 的 `plan.md` 是当前容量组合唯一真相源；
   memory 的“当前状态指针”只是 `t2ag_state_refresh.py` 生成的恢复缓存，不得反向拥有成员或预算。
   - 换组仪式先写 group plan，再运行 state refresh。
   - memory 与 plan 冲突时，以 plan 为准并修复 GENERATED 指针。
2. **全库禁止枚举式当前容量清单**：学生档案、learning_path 人工正文、任何 .md 不得手写"当前课程：A、B、C"。
   需要引用时只写指针，且**不得硬编码组代码**：
   - ✅ `当前课程组：见 memory 指针（成员见对应组文件）`
   - ❌ `当前课程组：G01` （组代码副本，换组即腐烂）
   - ✅ `当前课程：IV1001（见组文件）`（单课引用带指针，合法）
3. `main/10_student/profile/learning_path.md` 的课程生命周期和容量状态是机器生成缓存：
   - 生命周期取自各课程 `progress.md`。
   - 容量状态取自当前 active G 文件和 planned G 文件。
   - 由 `70_tools/t2ag_state_refresh.py` 统一刷新；生成区块禁止手写。
4. **定律入档**（problemlog 永久条目）：凡手写两遍的信息必然不一致——进度、版本号、课程清单已三次验证。解法恒为：删副本，留指针。

## 三、课程组的双线性质（设计意图，供组建档时参考）

每个组建议包含两类成员，配比随阶段流动：
- **项目线**（造外部的东西）：验收在世界一侧——能运行、有产出、可交付（如 PY1001+EG-0002）
- **语言线**（造内部的结构）：验收以卷面考核为主，过程指标为辅；题目只选编真题，不由 AI 生成。正文见 `main/50_playbook/exam_protocol.md`。

语言线默认期末权重：卷面 70%，过程指标 30%。卷面考核必须来自隔离的考核池；过程指标可含 mistake_bank 复发率、反例即答、盲判等。

结算真相源为各课 `40_course/<COURSE_ID>/_exam/exam_ledger.md`（复利回路·衰减实例）；
组级 `review.md` 只**引用**其结论，不复制——引用是读者，不是消费方。
上表末两条考试检查由 `runtime.exam_banks` 执行（空库短路 PASS）。
组文件成员表加一列「线别：项目/语言」，期末评估分别按各自标准验收，不得互相折算。

### 项目线验证条款

> 项目线课程每个里程碑必须绑定验证模式（A/B/B-K，建组或 M 启动前登记，大调整窗口可改未启动 M），任何模式必须满足三机制：外部真相源、独立性测量、失败留痕。
> 操作细则见 `50_playbook/project_verification.md`。

这里的“项目线课程”专指 `course_type: project`。`course_type: mastery` 即使采用
`learning_mode: project`，仍是 Mastery Course，只改变下一学习活动的排序策略，不触发
Project Course 的里程碑验收协议。

## 四、刚性与流动的边界（组运行规则）

> **执行参数化原则**：协议层只规定必须存在的机制，不固定参数值。周期结构、复盘位置、小调整频率、大调整频率等参数，在建组仪式或学生执行参数中生成；未讨论前使用下述协议默认值。
>
> **协议默认调整规则**：3-1-3 周期；每循环两次小调整（每次至多一处运行参数），每三个循环一次大调整窗口。

| 维度 | 规则 |
|---|---|
| 容器 | **刚性**。每组必须在 `plan.md` 写明 `container_mode` 及其容器与止损；容器形状可选，**有容器不可选**（两种形状见 §4.1） |
| 频率红线 | **刚性**。破线周期计入期末评估，连续两周期破线触发紧急复盘。**只管「有时间但没做」**，与进度停滞的后果边界见 §4.2 |
| 仪式 | **刚性**。复盘、调整、卷面考核、组级评估、结组仪式不可省略；具体频率由学生执行参数决定 |
| 范围 | **弹性**。可砍内容进下一组，砍必留痕（progress 记"未完成部分及去向"） |
| 配方 | **组间流动，组内冻结**。成员增删、换教材、课程状态转正只在结组仪式发生；组内只走小调整/大调整分级通道 |

### 4.1 两种容器形状（`container_mode`）

组级参数，**建组仪式登记、组内冻结**，改动只在结组仪式（配方级）。
新建组默认 `progress`。与 binding 的 `execution_mode: flexible` 无关，勿混。

| | `schedule` 严格日程 | `progress` 按进度 |
|---|---|---|
| 容器 | 循环日历（如 14 循环） | 里程碑序列（主干碑） |
| 刚性锚 | **日期不动** | **每碑的停留预算不动** |
| 弹性面 | 范围：学到哪考到哪 | 时间：预算内自由 |
| 期末 | 日历节点不后移，进度只闸组卷范围 | 碑达成才开卷，范围不缩 |
| 小测/建库 | 按循环号触发 | 按每 N 个主干碑触发 |
| 超限 | 未覆盖内容砍进下一组并留痕 | 进 §4.2 分诊 |

原理不变，只是换了坐标：`schedule` 固定 deadline、放开范围；`progress` 固定预算、放开时间。
**两种都不允许「既不限时也不限范围」**——那不是模式，是没有容器。

#### 容器参数由建组仪式产生，模板不预填（P-0077 连带，2026-08-22）

`calendar.md` 里三个容器参数——`cycle_length_learning_days`、
`keystone_dwell_budget_cycles`、`cycle_count`——**没有唯一正确答案**：
它们是建组仪式上依据上一组结组证据与用户确认**议出来的**，不是建组命令能一次答出的。
因此模板留字面 `TBD`，`t2ag_init.py new-group` **不为它们设 CLI 参数、更不设默认值**。

首次启动时，学生已经阅读并确认的“参考学习方案”可以承担本次议定：只要方案正文明确展示
了容量、时间形状和真实里程碑，模型就把这些已确认内容映射进 calendar/plan，随后由
`activate-group` 公证。不得把“planned → active”误当成第二次用户决策，再要求学生回复
“同意激活”；只有方案没有覆盖实质参数时才回到方案修订，而不是临时抛出内部字段。

与 `--source-language` 的对照，是同一条判据的两侧：

| | `--source-language` | 上述三个容器参数 |
|---|---|---|
| 有无唯一正确答案 | **有**（教材语言是客观事实） | **无**（是裁决产物） |
| 模型能否猜 | 不能 | 不该猜 |
| 取错的后果 | **静默错误**：T001 §9 术语纪律对着错语言执行 | 无——`TBD` 是可见欠账 |
| 结论 | **必填、无默认** | **模板留 `TBD`，不做参数** |

判据一句话：**给「有唯一正确答案且模型猜不出」的东西设必填参；
给「没有唯一正确答案」的东西留可见占位符。**给后者设必填参只会逼出一个随手填的假值，
那是把静默错误从一处搬到另一处，不是消除它。

`TBD` 未填时：`container_mode: progress` 下 `cycle_count` 本就不参与判定；
`keystone_dwell_budget_cycles` 未定则 §4.2 分诊的预算判据无从计算，此时按「锚未设」
如实报告，**不猜、不用建组日代替**（与 `calendar.md` 的 `cycle_anchor_learning_day: TBD` 同纪律）。

### 4.2 频率破线 ≠ 进度停滞（后果边界，勿合并）

这两件事看起来都像「落后了」，后果**完全不同**，合并即误伤：

| | 频率破线 | 进度停滞 |
|---|---|---|
| 含义 | **有时间但没做** | **没时间**，或**做不动** |
| 判据 | 学习频次低于执行参数红线 | 连续两循环，当前主干碑无推进证据 |
| 后果 | 计入期末评估；连续两周期触发紧急复盘 | **不计入成绩与掌握评估**，只触发一次分诊问句 |

分诊只有三个出口，学生答一句即可，**答什么都不扣分**：

```text
连续两循环无推进
      │
      ├─「卡住了」──▶ 紧急复盘通道：诊断依赖链，可砍范围或回补前置
      ├─「没空」────▶ 转 lifecycle_status: paused（progress_tracking.md，2026-08-19 增）
      │                记停点与恢复条件；钟停、组级容量释放
      └─ 不表态 ────▶ stalled 未分诊：doctor **WARN**，不阻断
```

**红线防的不是暂停，是沉默漂移。** 集训、家事、状态崩了都是合法暂停——宪法序言
本就假设操作者会疲惫；把暂停算成失分，等于用系统去惩罚它声称要接住的那种日子。
唯一无人接管的是「既没声明暂停、也没进复盘、就这么飘着」，那才是 WARN 的对象。

`paused` 成员在结组仪式顺延进下一组，**不算未完成欠账**；它不在 §六
「成员生命周期非法」名单（planned/completed/dropped）内，结组仪式本身是配方级释放阀。

### 4.3 碑序列锚（progress 组，防沉默缩范围）

§4.2 防的是**时间上的沉默漂移**，本节防**范围上的沉默漂移**——同一条不变量：
系统不怕改，怕不留痕的改。机器不判某次砍碑对不对（那是复盘里的裁决在人），
只判「砍碑走没走门」。三件套：

1. **碑序列锚**：`progress` 组激活（建组仪式）时，把主干碑序列冻进本组 `plan.md`
   「主干碑序列」节（每碑一行，格式 `- K01 描述`），frontmatter 记碑数锚定值
   `keystone_total_frozen: N`。planned 阶段的碑表是草案，不冻结、不记锚。
   **激活的唯一机器入口是 `t2ag_init.py activate-group`**（2026-08-22 用户裁决）：
   组只能生为 planned（`new-group` 不收 active——active 是仪式产物，flag 造出它
   就是「状态先出现、判断没发生」，P-0077 同族）；activate-group 是公证人而非裁判
   ——拒绝模板占位碑行，数真实碑行落锚，锚不得手写。逐碑确认本身仍是人的动作，
   发生在两条命令之间的 `plan.md` 编辑里。
2. **碑变更台账**：砍碑的唯一合法入口是 `plan.md`「碑变更台账」表加一行
   （日期｜碑号｜触发来源＝复盘/分诊出口｜去向组）。**故意粗**：不强制绑定复盘记录
   ID——后果层级只到对账，不值得为它建引用校验（同 §4.2 的 14 天游标判断）。
3. **对账检查**（doctor，扩 `check_groups` 不加新 ID）：active `progress` 组
   「当前碑数 + 台账砍碑行数 = 锚定值」，对不上 → FAIL；缺锚或缺序列节 → FAIL。
   开卷时组卷清单还须引碑序列快照对账（`exam_protocol.md` §七）——洗范围唯一能
   兑现的时刻是考试，校验放在兑现点。

**加碑不设门**：范围只许砍着弹，加碑是加范围，写台账一行即可（锚定值随之上调并留痕）。
`schedule` 组不适用本节——它的范围本来就是弹性面，砍进下一组走 §四 既有留痕即可。

**planned 阶段没有台账**：台账是**冻结之后**的留痕装置。planned 组的碑表还是草案，改草案
不需要留痕，直接改；此时若已经写了砍碑行，公证人只会把锚冻成当前碑数，而对账要的是
「当前碑数＋砍碑行数」——组当天激活成功、下一次 doctor 必 FAIL。`activate-group` 因此在
激活前就拒绝这种组，理由与出口一并给出：把砍掉的碑从草案里删掉，台账留空。

**激活前置检查一次报全**：`activate-group` 的所有判据在同一次拒绝里列全，不是首条即抛
——逐条抛会把一次拒绝拆成三轮「改一处、再跑、又红」。判据与 doctor **严格同源**：
不加严（加严会拦下 doctor 本会放行的组），也不放宽（放宽只是把同一个 FAIL 推迟一轮）。
止损锚与碑账对账两条原本只在激活**之后**的 doctor 点火，现已前移到激活时点；
全组循环里的条款（planned 组照报）与 §4.2 的 14 天停滞分诊不前移——它们一个在 planned
态就点火、一个要等时间流逝，都不满足「激活时点可判」。**没前移不等于放宽**：那些条款的
强制面原样留在常驻 doctor。呈现规格（拒绝以什么身份出现、要不要停顿）见
`progress_governance.md` §八。

**首组没有上一组**：`plan.md` 的激活条件里「上一组结组证据」「上一组阈值达成」两条对
第一个课程组**不适用**——首组的容量与碑序列由首启的参考学习方案承担，学生在停顿 B 上
确认的就是它。不适用要在文件里说出来，不能靠留空默认过关：空着的勾选框和「本条不适用
（首组）」是两种不同的事实，后者才是可复核的。

> **调整分级边界**：小调整 = 运行参数；大调整 = 范围级；配方级 = 组成员/教材/课程生命周期，只在结组仪式或用户明确发起的容量重组中发生。
> 机械判断：凡是需要动组文件成员表或 progress 生命周期字段的调整，至少是大调整；凡是要加减课程或换教材，就是配方级。
>
> 原理：deadline 固定、范围弹性 = 完成率的全部秘密；组内换配方 = 学习版的"阴跌中失耐心离场"。
> 第一个完整闭环的叙事价值 > 组内任何具体内容——完成本身是对旧病史的证伪。

## 六、doctor 增检六条

| 检查 | 级别 |
|---|---|
| memory 指针指向的组文件不存在或状态非 active | FAIL |
| 全库 active 组数量 ≠ 1 | FAIL |
| active 组成员课程缺 `progress.md`，或生命周期为 planned/completed/dropped | FAIL |
| 组外 ongoing 课程被临时学习 | PASS；不自动改组 |
| 实际学习长期偏离容量组合 | WARN；建议复盘，不自动换组 |
| 权威链外的 .md 出现枚举式课程清单 | WARN |
| 考核池卷的题号引用出现在 lesson/exercise 文件 | FAIL |
| `papers/` 下有卷夹但 index 未登记，或 meta 缺列/缺解答页码 | WARN |
| `ongoing` 课程 `course.md` 无 `source_catalog:` | WARN |
| 有 `source_catalog:` 但 `diff_recorded` 解析不开 | FAIL |
| `source_catalog: none` 未写理由 | WARN |

> 末两条的字段结构、锚语义与**为什么缺失只判 WARN**（预画是可证伪的预测，
> 价值在取目录当轮的 diff；判 FAIL 会用强制力换掉信息），canonical 见
> `doctor_contracts.md` §九，此处不复制。

> 第四条实现口径：
> - **只抓枚举，单课引用合法**：匹配"当前课程"后同一行出现 **≥2 个课程代码**模式（`[A-Z]{2,}\d{3,}` 计数），单代码不触发。
> - **白名单**：active/planned group 的 `plan.md`（真相源本源）豁免，不被此条打扰。
> - 单课引用如 `当前课程：IV1001（见组文件）`不违规；若该课不在当前组成员表内，doctor 顺手送一条 WARN "引用过时"。
